| 灯 | 含义 | 本轮 |

| 绿 | 可以按当前成交逻辑使用 | 收费公式、默认路由、直连 Pancake、10 个钱包同时下单 |

**总灯：黄。**

三句话：

1. 线上 FeeRouter（`0xBc2949…FEa5`）费率 35（0.35%），未暂停，owner 与 treasury 都是 `0xDE54…5e1C`。本地分叉上买入 0.05 BNB 的手续费事件正好是 0.000175 BNB。
2. 没有发现能把用户的币或 treasury 的币转走的严重漏洞。
3. 「一键预授权」在本包源码里授给的是交易场地（Pancake / Flap / FOUR），真正收费成交授给的是 FeeRouter。这两套如果在生产没有另外改写，最优模式会先授错对象。旧报告把这项写成通过，本轮改成实测后不通过。

## 3. 安全发现

| 严重度 | 题目 | 对用户意味着什么 |
|--------|------|------------------|
| 中 | 预授权和收费成交不是同一个合约 | 最优模式下，一键预授权可能授给 Pancake 或 FOUR，模拟却检查 FeeRouter，于是提示未授权。真正下单时还会按这一笔的数量再授给 FeeRouter，不会把币转到任意地址 |
| 中 | 收费合约允许调用方指定 Pancake / Flap 地址 | 官方页面写死了官方场地。自己改客户端或填写自定义路由时，这一笔的净额会授给那个地址。FOUR 内盘有官方地址校验，不受这一条影响 |
| 低 | 改费率、暂停、取回合约残留的钥匙是同一个 treasury | 合约不能升级。最坏是费率被调到上限 10%，或交易被暂停后仍原样转发。用户没主动成交时，不会被抽走钱包里的币 |
| 低 | 空投合约地址可以被设置改成别的合法地址 | 收费地址改不了。空投地址改得了。能改本地保险库的人本来就能用里面的私钥 |
| 低 | 批量广播在「发出去了但节点说失败」时可能复用同一序号 | 可能卡单或要手动看哈希。正常连发的单测通过 |
| 无红灯 | 归集 / 分发 / 空投 | 本包里的计划不会自动打给 owner，也不会先删私钥。真正发送的控制器不在包里，没复跑到发送顺序 |

密钥保险箱：主密码经 scrypt 再 AES-GCM。单测覆盖了解不开、改一个字节就失败。备份完成后内存里的密钥被清掉。
